# 发布验证

日期：2026-11-07。本次验证针对整理后的发布副本，不复用旧报告来证明新代码通过。

## 主机验证

| 验证项 | 范围 |
|---|---|
| 控制器 | 260 项：启动、采样超时、锁定、换向、热平衡及方向检测等 |
| TMP117 | 6 项：ID、配置、温度换算、状态和读取错误 |
| 配置存储 | 39,829 个检查点、22 组：持久化、CRC、损坏及失败处理 |
| 普通接口 | 70 项：真实主程序处理函数配合外围模拟，包含检测中主循环停止请求 |
| 调试接口 | 同一组 70 项在调试入口开启时重跑，包含来源拒绝、唤醒、方向状态与保存失败 |
| 网页 | 44 项：嵌入 HTML/JavaScript、表单、停止队列、断线、方向与故障显示 |
| 网页布局 | 浏览器检查 320~1440 像素的 9 个宽度，并人工检查桌面与手机截图 |
| 固件 | 普通 `pl530_tec` 与调试 `pl530_tec_debug` 两套构建 |
| PCB 文件 | 原文件 SHA-256 一致，保留原始内容 |

最终实际执行结果、源码及二进制校验值由 [发布清单](发布清单.json) 记录。主机测试入口是 `node tools/test.mjs`，网页入口是 `npm run test:web`；两套固件可使用 `pio run -e pl530_tec -e pl530_tec_debug -j 1` 编译。

编译曾在并行任务下因本机内存不足中断，最终使用单任务重新编译。该中断不是已经完成的验证结果。

## 检查边界

主机控制器测试定义 `ARDUINO` 和 `ESP32`，但未定义 `ESP_PLATFORM`。因此部分实机故障处理、毛刺过滤、PWM 限幅及停机延时分支没有被同一组测试执行；不能把 260 项通过解释为这些实机路径已验证。

主机控制器使用默认历史三秒检测时序；实机主程序设置四秒与更长停机，并由实机分支限制至 30% PWM。网页测试以模拟接口检查显示和队列，不证明实物脉冲、电流或热响应。

接口测试使用真实 `main.cpp`，但驱动器、传感器、WiFi、NVS 和定时器是模拟对象。编译检查真实 ESP32 工具链能构建，不检查功率输出效果。

发布清单是文件校验记录，不是认证报告。修改文件、工具、依赖或构建配置后，旧清单不再代表新状态，须重新测试、编译并生成。`node tools/verify_release.mjs` 用于检查公开文件是否仍与清单一致；生成命令 `--write` 只汇总本机结果，不自动执行完整验证。
