# 2026-11-12 故障复核

基线为 GPLv3 提交 `c62613dfc17dae0a9b3f7ca8ed54f127c62c8a2b`。复核范围包括两版温控器、采样、方向检测、存储、接口、网页和日志验收。以下五类问题先加入失败用例，再修改实现；没有把主机测试解释为实机性能证明。

## 1. 短时驱动告警可能丢失

通电后捕获的 nFAULT 下降沿可能到 ISR 执行时已恢复高电平。旧实机代码会丢弃该边沿，轮询还会在引脚恢复高电平时清除待处理记录。首次 PWM 写入时监测尚未开启，检测脉冲另有 5 ms 屏蔽期，因此短告警可以不触发锁定。

修复后在两个 PWM 通道仍为零时完成唤醒等待，并在首次非零 PWM 前开启监测。ISR 保留已捕获边沿，轮询保留待处理中断及锁存记录，故障必须经显式复位后才能重新启用。取消有功阶段的 15 µs 软件复读过滤和 5 ms 告警屏蔽。

复现用例：`first_control_pwm_fault`、`first_calibration_pwm_fault`、`queued_powered_fault_survives_poll`。两版基线的实机条件构建均失败，修复后通过；原有缓存关闭、换向和停机边界用例也在实机条件构建中运行。

## 2. 超时记录与物理关断不原子

旧实机定时器先解锁，再调用 LEDC、等待 2 ms，最后拉低 nSLEEP。PWM 驱动调用和另一核心的新采样可以插入这个间隙：关断依赖外围调用完成，旧回调还可能关掉已经重新许可的新输出。普通停止也在拉低 nSLEEP 前依赖 LEDC 和固定延时。

修复后定时器在同一临界区内设置锁存标志并直接写 GPIO 关断寄存器，不调用 LEDC、不延时。主循环停止先拉低 nSLEEP，再清零 PWM；换向的休眠等待仍保留。

复现用例：`watchdog_without_peripheral_calls`、`watchdog_cut_before_unlock`。第二项在解锁瞬间模拟另一核心提交有效采样，确认旧回调不会事后误切新输出。两版旧实机分支均失败，修复后通过。

## 3. 精密 PID 稳定窗口要求了不存在的采样率

旧窗口同时要求约 120 秒和至少 500 个样本。主程序在读取结束后才等待下一个 200 ms 间隔，软件 I²C 读取增加了实际周期；267 ms 等有效周期在窗口内不足 500 个样本，即使原始温度一直达标也无法报告稳定。

修复后依据连续窗口时长判断就绪；1 秒采样间隙、目标改变和无效样本仍使证据失效。最大目标误差 10 mK、峰峰值 20 mK 的判据保持不变。`unfiltered_window_real_poll_cadence` 覆盖 267/300/399 ms 间隔及毫秒计数回绕，旧代码失败、修复后通过。

## 4. 日志可以在控制量损坏时通过验收

旧工具虽然解析滤波温度、占空比及 P/I/D，却没有检查这些列是否为有限数值；原始温度平稳时，即使占空比为 NaN、Infinity 或超出 100%，也可能报告通过。库函数的测量区间参数也缺少完整验证。

修复后检查所有数值列、传感器温度范围、目标与输出范围，以及有限且有效的测量区间。验收统计继续只使用未滤波温度。新增三个测试组覆盖这些输入，原先出现 21 个失败子用例，修复后全部通过。

## 5. 调试命令绕过完整输入与保存检查

旧调试 HTTP 会把 `1junk` 等输入经 `toInt` 截断后执行，甚至在没有 PWM 参数时自动唤醒。UART 的 `r/n/u` 忽略方向保存或应用的失败，`r/n/d` 还隐式清除故障；`d` 跳过检测前的持久化旧方向清除和完成结果处理。最坏情况下，检测失败并重启后继续使用旧接线方向。

修复后 PWM 参数先完整验证为范围内整数，wake 只接受精确 `0/1`，无效参数不改变输出。UART 与 HTTP 共用方向保存、检测启动和结果处理流程；旧方向清除失败不发脉冲，保存或应用失败打印 `REJECTED`，解除故障保留为独立命令。原有有效调试指令仍可使用。

`debug_arguments_reject_before_mutation`、`serial_direction_checks_save_and_state`、`serial_calibration_invalidates_and_saves` 在修改前均失败。调试集成测试现在定义 `ARDUINO/ESP32`，通过模拟 UART 输入执行真实主循环；同一组 73 项回归也用于精密 PID 副本。

## 验证与实际边界

`npm test` 包含 13 组主机套件，其中两版控制器各编译、执行普通和 `ESP_PLATFORM` 版本；两版网页测试共 90 项，日志工具 12 项。普通、调试和精密 PID 固件分别编译。具体结果和文件哈希见 [发布验证](发布验证.md) 及 [发布清单](发布清单.json)。

此次保留既有采样恢复策略、硬温度纠正策略、调试能力及 GPL-3.0-only 许可。采样恢复仍可能自动重启之前启用的控制；调试强制唤醒仍是明确的保护旁路，行为见 [调试接口](调试接口.md)。接口的来源检查不是用户身份认证，仍按可信局域网部署。

改后的通电阶段 nFAULT 瞬态会触发锁定，可能暴露之前被软件过滤掩盖的供电、接线或驱动问题。没有重新烧录、实测 TEC 或修改 PCB；需要在有外部限流、可切断功率的条件下验证唤醒、换向、停止时的电压与电流。软件中断与软件定时器不能替代独立硬件保护，也不能检测探头脱落但仍返回合理温度的全部情况。
