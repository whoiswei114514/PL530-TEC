# 调试接口

## 重要警告

**调试接口已保留，但不是普通控制接口。强制唤醒和手动 PWM 会绕过方向确认、温度有效性、采样超时停机及部分驱动器故障停机路径。可能在探头断线、温度失控或 nFAULT 低电平时保持驱动使能。**

普通环境 `pl530_tec` 默认 `PL530_ENABLE_UNSAFE_DEBUG=0`，以下 HTTP 入口不注册，串口字符不会触发调试命令。环境 `pl530_tec_debug` 设置为 `1`，保留原有调试能力，启动日志会打印风险警告。

调试仅用于有现场人员、限流电源、正确散热与可直接切断功率的台架。不要在无人值守、公共 WiFi 或公网使用调试固件。完成调试后烧回普通固件。

**没有软件自动截止时间，强制唤醒可持续保持。** 网页 `/api/control/stop` 不能作为退出强制唤醒的可靠替代；明确退出强制唤醒后仍应核对输出，必要时直接硬件断电。

## HTTP 接口

仍保留历史 GET 形式以兼容原工具。尽管是 GET，`wake`、`pwm` 都会改变硬件状态，禁止被代理、链接预取或监测程序自动访问。它们现在也要求 `X-PL530-Request: 1` 和正常接口相同的 Host/Origin 校验；不能只在浏览器地址栏打开。

| 方法 | 路径 | 参数 | 行为 |
|---|---|---|---|
| GET | `/api/debug/status` | 无 | 返回强制唤醒、nSLEEP、nFAULT、PWM 计数、温度和状态 |
| GET | `/api/debug/wake` | `state=1` | 保持 nSLEEP 高，可能绕过停机保护 |
| GET | `/api/debug/wake` | `state=0` | 清零 PWM 并退出强制唤醒，拉低 nSLEEP |
| GET | `/api/debug/pwm` | `in1`、`in2` | 自动进入强制唤醒，直接设置两路 PWM 计数 |
| POST | `/api/control/set-direction` | `direction=normal/reversed/unknown` | 跳过热响应判定，人工指定并保存方向 |

PWM 计数范围是 0~1023，不是百分比。接口沿用 `toInt` 与限幅逻辑，省略计数按 0 处理；不应依赖它替你验证输入。两路同时非零可能产生制动或其他换流状态，禁止未经硬件分析随意组合。

人工方向接口要求停止控制、退出强制唤醒、驱动器休眠、无活动检测且无锁定故障；保存失败返回错误，不再无条件声称成功。但方向是否真实正确仍由操作者承担，错误方向可能把保护制冷变成加热。

`normal` 表示 IN1 制冷、IN2 制热；`reversed` 表示 IN1 制热、IN2 制冷；`unknown` 清除正常控制许可。该接口不会自动清除故障，故障应单独排查。

建议先仅检查状态和退出路径：

```powershell
curl.exe http://192.168.1.1/api/debug/status
curl.exe -H "X-PL530-Request: 1" "http://192.168.1.1/api/debug/wake?state=0"
```

如果已经手动驱动，`in1=0&in2=0` 只清零 PWM，**不会退出强制唤醒**；仍需 `wake?state=0` 或串口 `s`。

没有鉴权令牌、账户认证或 TLS。请求头的值 `1` 不是秘密，同网设备可自行添加；来源校验不意味着调试模式安全。

## UART 命令

仅调试构建启用，115200 波特率，GPIO43/44 的 UART0 接外置 3.3 V 下载器。命令是单字符，不需要回车；每个收到的有效字符都可能立即执行。

| 字符 | 动作 |
|---|---|
| `w`、`W` | 强制唤醒，保持 nSLEEP 高 |
| `s`、`S` | 清零 PWM，退出强制唤醒并休眠 |
| `0` | 清零 PWM，但不退出强制唤醒 |
| `7` / `8` | IN1 / IN2 约 5% PWM |
| `3` / `4` | IN1 / IN2 约 10% PWM |
| `A` / `a` | IN1 / IN2 约 15% PWM |
| `B` / `b` | IN1 / IN2 约 20% PWM |
| `e` | IN2 约 25% PWM |
| `1` / `2` | IN1 / IN2 约 30% PWM |
| `5` / `6` | IN1 / IN2 约 50% PWM |
| `9`、`f`、`F` | IN2 100% PWM，没有正常闭环保护 |
| `r`、`R` | 手动设为 reversed 并尝试保存 |
| `n`、`N` | 手动设为 normal 并尝试保存 |
| `u`、`U` | 手动设为 unknown 并尝试清除方向记录 |
| `c`、`C` | 请求解除故障 |
| `d`、`D` | 退出强制唤醒并尝试直接开始方向检测 |
| `?`、`h`、`H` | 打印历史命令帮助 |

大小写并不总等价，例如 `A` 与 `a` 控制不同通道。PWM 字符会自动强制唤醒；不要把串口当文本交互窗口随意输入。

历史 UART 的手动方向/检测命令仍保留其原始快速路径，**没有正常 HTTP 检测同等的持久化清除和完整返回值检查**。串口中的“已保存”等历史文本不一定代表保存或应用成功，应读取 `/api/status` 并重新启动核对。UART `d` 可能没有先清除旧的 NVS 方向，重启后可能恢复旧映射。

串口日志中“纯直流 3.3 V”等历史说法不是电压测量；实际 TEC 电压由外部母线和 H 桥决定。不要把“0”理解为所有电源都已断开。

## 哪些保护不能依赖

强制唤醒标志会改变 `disableDriver()`、故障中断以及采样定时器中的关断行为。直接 PWM 不走正常温控曲线，也没有方向自动判定；状态机显示停用或某一故障时，手动输出与状态显示仍可能不一致。

DRV 芯片的硬件保护和外置电源限流是否有效需要实测，软件调试接口不能保证这些机制。nFAULT 拉低时应退出调试、断开功率并检查原因，不要持续强制驱动。
