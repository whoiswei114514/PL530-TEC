# 调试接口

## 先说清楚几件事

普通固件 `pl530_tec` 默认设为 `PL530_ENABLE_UNSAFE_DEBUG=0`，下面所有 HTTP 和串口调试指令都不会编译进来。只有刷入 `pl530_tec_debug` 才会开启，开机串口也会打印提示。

**强制唤醒（Force Wake）和手动 PWM 会绕过方向确认、温度有效性检查、采样超时停机以及部分 `nFAULT` 关断路径，而且没有软件自动超时。** 也就是说探头掉了、温度跑飞或驱动报错时，输出仍可能保持使能。

另外要留意：`in1=0&in2=0` 或者串口按 `0` 只把占空比归零，**不会**退出强制唤醒；必须发 `wake?state=0` 或串口按 `s` 才会把 `nSLEEP` 拉低退出来。调试建议只在有人盯着的台架上跑，配好限流电源、散热器和能直接断掉功率的物理开关，调完记得刷回普通固件 `pl530_tec`。

## HTTP 调试接口

为了兼容早期调试脚本，这里沿用了 GET 路由，但同样强制检查 `X-PL530-Request: 1` 请求头和 Host/Origin 同源校验，不能直接在浏览器地址栏里打开。设备无密码认证和 TLS，只在可信局域网用就行。

| 方法 | 路径 | 参数 | 行为 |
|---|---|---|---|
| GET | `/api/debug/status` | 无 | 返回强制唤醒、`nSLEEP`、`nFAULT`、PWM 计数、温度与状态 |
| GET | `/api/debug/wake` | `state=1` | 拉高 `nSLEEP` 保持唤醒，可能绕过停机保护 |
| GET | `/api/debug/wake` | `state=0` | 清零 PWM 并退出强制唤醒，拉低 `nSLEEP` |
| GET | `/api/debug/pwm` | `in1`、`in2` | 自动进入强制唤醒，直接设置两路 PWM 计数 |
| POST | `/api/control/set-direction` | `direction=normal/reversed/unknown` | 跳过热响应测试，人工指定并保存方向 |

`in1`、`in2` 传入的是 **0~1023 的 PWM 计数**（10 位），不是百分比；未传的参数会按 `0` 解析。两路千万别同时给非零值，否则会产生制动或异常换流。

人工设置方向接口要求先停用温控、退出强制唤醒、驱动处于休眠、没有正在跑的检测且无锁定故障，NVS 保存失败会直接返回错误。`normal` 表示 `IN1` 制冷 / `IN2` 加热，`reversed` 相反，`unknown` 清除已保存的方向许可（它不会顺便清故障，故障需单独排查并调用复位故障接口）。

常用状态查询和退出强制唤醒示例：

```powershell
curl.exe http://192.168.1.1/api/debug/status
curl.exe -H "X-PL530-Request: 1" "http://192.168.1.1/api/debug/wake?state=0"
```

## UART 串口命令

仅 `pl530_tec_debug` 开启，115200 波特率，走 GPIO43/44 的 `UART0` 接外置 3.3 V 下载器。**单字符立即触发，不需要按回车**，而且大小写有区分（比如 `A` 和 `a` 控制不同通道），打开串口工具时别随手乱敲字符。

| 字符 | 动作 |
|---|---|
| `w`、`W` | 强制唤醒，保持 `nSLEEP` 为高 |
| `s`、`S` | 清零 PWM，退出强制唤醒并休眠 |
| `0` | 清零 PWM（不退出强制唤醒） |
| `7` / `8` | IN1 / IN2 约 5% PWM |
| `3` / `4` | IN1 / IN2 约 10% PWM |
| `A` / `a` | IN1 / IN2 约 15% PWM |
| `B` / `b` | IN1 / IN2 约 20% PWM |
| `e` | IN2 约 25% PWM |
| `1` / `2` | IN1 / IN2 约 30% PWM |
| `5` / `6` | IN1 / IN2 约 50% PWM |
| `9`、`f`、`F` | IN2 100% PWM（无闭环保护） |
| `r`、`R` | 手动设为 `reversed` 并尝试保存 |
| `n`、`N` | 手动设为 `normal` 并尝试保存 |
| `u`、`U` | 手动设为 `unknown` 并尝试清除方向记录 |
| `c`、`C` | 请求解除故障 |
| `d`、`D` | 退出强制唤醒并尝试直接开始方向检测 |
| `?`、`h`、`H` | 打印命令帮助 |

## 几个历史遗留坑

- **串口方向命令比较糙**：`r`、`n`、`u`、`d` 走的是早期快速路径，没有 HTTP 接口那么完整的前置校验和错误检查。比如串口按 `d` 可能不会先擦掉 NVS 里旧的方向记录，重启又恢复成老映射；串口打印出来的“已保存”也未必代表真正写进去了，改完方向最好查一下 `/api/status` 再重启核对一遍。
- **串口历史打印文字**：日志里诸如“纯直流 3.3 V”之类的旧提示不是实际电压测量值，H 桥母线电压只看外部 DC-DC 和万用表；PWM 设 `0` 也只代表停止开关脉冲，功率级供电还在。
- **`nFAULT` 处理**：强制唤醒期间 `disableDriver()`、故障中断和采样定时器的关断行为都会被改写；一旦看到 `nFAULT` 拉低，先把强制唤醒退掉、断开外部功率供电排查硬件原因，搞定再继续测。
