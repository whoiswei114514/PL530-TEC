# 编译与烧录

下面默认编译根目录原版固件。放在 `firmware/precision_pid/` 下的独立精密 PID 实验版，使用方法和参数整定见 [新版说明](../firmware/precision_pid/README.md)。

## 编译环境

工程固定使用 PlatformIO Core `6.1.19`、`espressif32@7.0.1` 和 Arduino-ESP32 `2.0.17`（依赖已在 `platformio.ini` 里锁好，不要随意跨大版本升级 Arduino 框架）。

配置文件基于 `esp32-s3-devkitc-1` 板卡定义，并显式覆盖为 8 MB Flash、`qio_opi` 和八线 PSRAM 来适配 N8R8 模组。构建摘要里如果仍显示基础板卡的 “No PSRAM” 不用管，实际 PSRAM 初始化结果以串口开机日志为准。

在仓库根目录执行：

```powershell
python -m pip install platformio==6.1.19
pio run -e pl530_tec -j 2
```

如果 `pio` 没进系统 PATH，直接用 `python -m platformio` 替代，或者使用本机已有 PlatformIO 可执行文件。

普通固件 `pl530_tec` 默认关闭调试入口；需要台架手调时再编译调试版：

```powershell
pio run -e pl530_tec_debug -j 2
```

调试构建不会改串口日志等级，而是开放能直接拉起驱动和 PWM 的 HTTP 与串口命令，烧之前建议先看 [调试接口](调试接口.md)。

## 独立精密 PID

同样在仓库根目录执行：

```powershell
pio run -d firmware/precision_pid -e precision_pid -j 1
pio run -d firmware/precision_pid -e precision_pid -t upload --upload-port COM10
```

新版使用独立的 NVS 命名空间，首次烧录后记得重新执行一次方向检测。整定和串口日志分析见 [新版说明](../firmware/precision_pid/README.md)。

## 外置串口接线

用 CH343、CH340 等 3.3 V 逻辑电平的 UART 下载器：

| 下载器 | 主板 |
|---|---|
| TXD | GPIO44 / 模组物理引脚 36 |
| RXD | GPIO43 / 模组物理引脚 37 |
| GND | GND |

主板单独供好电，不要把下载器的 5 V 接到主板 3.3 V 电源轨上，也不要同时并接两路电源；串联限流电阻不能替代电平转换。

原板 PCB 没画板载 USB 口。以前现场调试试过从 GPIO19/20 飞线用原生 USB，日常还是走外置串口省心（留意 GPIO18 不是 USB D-）。

## 烧录步骤

烧录前先把 TEC 停掉，断好功率供电。板子没接自动下载电路的话，按手动 BOOT/RESET 时序进下载模式：

1. 按住 BOOT 不放。
2. 按一下并松开 RESET。
3. 再松开 BOOT。
4. 运行上传命令烧录（`platformio.ini` 里配了 `--before no_reset` 配合手动进模式）。
5. 烧完按一下复位或重新上电即可。

```powershell
pio device list
pio run -e pl530_tec -t upload --upload-port COM10
pio device monitor --port COM10 --baud 115200
```

把示例里的 `COM10` 换成实际端口（Linux 下通常是 `/dev/ttyUSB0`）。

注意 `.pio/build/pl530_tec/firmware.bin` 只是应用镜像，**不是包含 bootloader 和分区表的整片镜像，千万别手动写到地址 `0x0`**，走 `pio run -t upload` 会自动按偏移刷入。

## 本地测试

主机 C++ 测试需要 Node.js 22+ 和支持 C++17 的 `g++`：

```powershell
node tools/test.mjs
```

如果 `g++` 不在 PATH 里，可以把环境变量 `CXX` 指到它的绝对路径（Windows 下脚本会自动把编译器目录加进子进程 PATH，免得缺运行时库）。

网页回归测试依赖 Playwright：

```powershell
npm ci
npx playwright install chromium
npm run test:web
```

本机已有浏览器或 Playwright 时，也可以通过 `CHROME_PATH` 和 `PLAYWRIGHT_MODULE` 指定。网页测试用 Playwright 网络拦截模拟设备响应，不需要真板子或本地 HTTP 服务。

执行 `npm test` 会一并跑原版与精密 PID 版的 C++ 测试；新版网页与日志分析脚本测试另跑这两条：

```powershell
node firmware/precision_pid/tests/web_ui_test.cjs
python firmware/precision_pid/tests/test_analyze_log.py
```

测试产物分别放在 `test-results/` 和 `firmware/precision_pid/test-results/`（均在 `.gitignore` 内）。具体覆盖项与实机测试记录见 [发布验证](发布验证.md)。
