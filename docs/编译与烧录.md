# 编译与烧录

以下默认编译根目录原版。独立精密 PID 新版位于 `firmware/precision_pid/`，未经实机验证，不覆盖原版源文件。

## 工具与配置

发布使用 PlatformIO Core 6.1.19、`espressif32@7.0.1`、Arduino-ESP32 2.0.17。依赖按 `platformio.ini` 固定，不建议未经验证直接升级 Arduino 主版本。

工程使用 `esp32-s3-devkitc-1` 基础板定义，并显式配置 8 MB Flash、`qio_opi` 与 PSRAM，适配 N8R8 模组。构建摘要可能显示基础板的“No PSRAM”，运行时初始化结果请查看串口日志。

在仓库根目录执行：

```powershell
python -m pip install platformio==6.1.19
pio run -e pl530_tec -j 2
```

若 `pio` 未加入 PATH，可使用 `python -m platformio`；已有 PlatformIO 安装也可以直接使用其可执行文件。

普通构建默认关闭直接调试入口。确需现场调试时显式构建：

```powershell
pio run -e pl530_tec_debug -j 2
```

调试构建不提高日志等级，而是开放能直接影响输出的 HTTP 与串口命令。先阅读 [调试接口](调试接口.md)。

## 独立精密 PID

仍在仓库根目录执行：

```powershell
pio run -d firmware/precision_pid -e precision_pid -j 1
pio run -d firmware/precision_pid -e precision_pid -t upload --upload-port COM10
```

新版使用独立 NVS 参数区，首次烧录后重新检测 TEC 方向。整定、原始温度日志和恒温判定步骤见 [新版说明](../firmware/precision_pid/README.md)。

## 外置串口接线

使用 3.3 V 逻辑的 CH343、CH340 等 UART 下载器：

| 下载器 | 主板 |
|---|---|
| TXD | GPIO44 / 模组物理引脚 36 |
| RXD | GPIO43 / 模组物理引脚 37 |
| GND | GND |

主板需要自己的正确供电。不要把下载器 5 V 接到 3.3 V 电源轨，也不要未经核对同时并接两路电源。串联电阻不是电平转换器。

原 PCB 不提供板载 USB 接口。历史调试曾通过 GPIO19/20 飞线使用原生 USB，但本仓库不把飞线作为标准烧录方式；GPIO18 不是 USB D-。

## 下载步骤

先停用 TEC，并确保功率输出有可靠硬件断开方式。没有确认自动下载电路时，使用手动 BOOT/RESET：

1. 按住 BOOT。
2. 按下并松开 RESET。
3. 再松开 BOOT。
4. 按实际设备选择串口，上传固件。
5. 上传完成后松开 BOOT，复位或重新上电。

```powershell
pio device list
pio run -e pl530_tec -t upload --upload-port COM10
pio device monitor --port COM10 --baud 115200
```

将示例中的 `COM10` 替换为实际串口；Linux 使用 `/dev/ttyUSB0` 等设备名。配置中的 `--before no_reset` 配合手动 BOOT/RESET 进入下载模式。

普通应用文件位于 `.pio/build/pl530_tec/firmware.bin`。**这是应用镜像，不是完整 Flash 镜像，不能写到地址 0。** 推荐使用 PlatformIO 上传流程处理 bootloader、分区表与应用偏移，不套用旧烧录脚本。

## 测试

主机测试需要 Node.js 22 或更新版本，以及支持 C++17 的 `g++`：

```powershell
node tools/test.mjs
```

编译器不在 PATH 时设置 `CXX` 为其绝对路径。Windows 下脚本会把该目录加入子进程 PATH，以便加载编译器运行库。

网页测试需要：

```powershell
npm ci
npx playwright install chromium
npm run test:web
```

可用 `CHROME_PATH` 指定已有 Chrome，用 `PLAYWRIGHT_MODULE` 指定已有 Playwright 包。网页使用浏览器网络拦截模拟设备，不启动本机 HTTP 服务，也不接通 TEC。

`npm test` 同时检查原版与新版。新版网页和日志工具测试另行执行：

```powershell
node firmware/precision_pid/tests/web_ui_test.cjs
python firmware/precision_pid/tests/test_analyze_log.py
```

原版测试产物生成在根目录 `test-results/`，新版网页截图在 `firmware/precision_pid/test-results/`，不纳入版本库。软件测试范围与样机实测记录见 [发布验证](发布验证.md)。
