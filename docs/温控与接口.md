# 温控与接口

本页介绍根目录原版固件的控制逻辑与 HTTP 接口。独立精密 PID 实验版的算法与新增接口见 [精密 PID 实验版](../firmware/precision_pid/README.md)，两版共用下面的硬件保护与方向检测流程。

## 温控算法

原版固件采用“非线性接近 + 热平衡修正”策略：

- 当温度落在网页设定的 PWM 高低温范围之外时，目标占空比直接给到 100%；进入区间接近目标时，按误差曲线逐渐收小占空比，并受变化率限速约束。
- 进入平衡区时会先承接当前驱动输出，只有从静止直接起步时才给约 10% 初值；之后依据温差和温升速率动态修正平衡驱动，10% 并不是死下限，稳态下允许更低、归零甚至换向。
- 固件先对采样温度滤波，逻辑占空比正值代表加热、负值代表制冷。`normal` 映射为 `IN1` 制冷、`IN2` 加热，`reversed` 对调两路。实际冷热对应关系由 TEC 接线和探头位置决定，靠方向检测确定。

## 保护机制

- **上电默认停用**：NVS 只保存目标温度、高低温限和方向，不保存启用状态，每次上电 TEC 都保持关闭。
- **出力前置条件**：方向为 `unknown`、保护初始化失败或缺少有效温度读数时，不允许正常驱动。
- **10/55 °C 硬限保护**：原始温度越过 10 °C 或 55 °C 硬限制时，只要当前已启用且方向可信，就会尝试全力纠偏；若约 10 秒没有好转或累计约 30 秒仍未拉回安全区，则锁定停机。
- **采样超时与恢复**：传感器超过 1 秒无有效数据时，独立约 50 ms 软件定时器会介入关闭驱动（彻底物理断电仍依赖外部电源开关）。**有效温度恢复后，固件会自动解除采样超时，并恢复超时之前的启用状态。**
- **不可自动恢复的故障**：`nFAULT` 驱动器故障、热失控锁死和保护初始化失败不会按上述方式自动恢复，需排查或人工解除。
- **实机编译分支**：真机 `ESP_PLATFORM` 分支带有上电启动等待、故障毛刺过滤和额外停机延时，测试边界见 [发布验证](发布验证.md#测试范围)。

## 方向检测

在网页确认后手动触发，共五步，总超时约 60 秒：

1. 采集约 2 秒正向基线。
2. 实机 `IN1` 以不超过 30% PWM 输出约 4 秒。
3. 停机回稳约 18 秒。
4. 采集约 2 秒反向基线。
5. 实机 `IN2` 以不超过 30% PWM 输出约 4 秒。

检测要求初始温度在 15~45 °C 之间；过程中触及 12/50 °C、超出当前设定的温度区间、样本无效或触发故障都会立即中止。只有正反向的原始温差和去漂移温差都符号相反且各自达到约 0.2 °C 时才会判定成功，含糊则直接失败。

启动检测前会先清除旧方向，新方向保存成功后才会生效，检测结束保持停用状态。检测期间网页仍可正常查询和提交停止指令。

状态接口里的 `rawDutyPercent` 是状态机内部请求值（检测期间可能显示 ±100），实际发往硬件的占空比由 `dutyLimitPercent=30` 限幅，单向脉冲时长由 `pulseMs` 返回。

## HTTP 接口

设备提供 HTTP 80 端口，没有登录认证和 TLS，依赖 `Host`（仅接受 AP 地址或当前 STA IP）、`Origin` 同源检查和写操作请求头 `X-PL530-Request: 1` 防护，请在可信局域网内使用，不要暴露到公网。

| 方法 | 路径 | 参数或内容 |
|---|---|---|
| GET | `/api/status` | 温度、状态、方向、PWM、传感器总线与 WiFi 状态 |
| POST | `/api/settings` | `target`、`high`、`low`、`enabled` |
| POST | `/api/control/stop` | 停用 TEC 并取消正在进行的方向检测（不写入启用状态） |
| POST | `/api/control/reset-fault` | 请求解除可解除的故障锁定 |
| POST | `/api/control/detect-direction` | `confirm=full_power` |
| GET | `/api/wifi/scan` | 异步扫描附近 WiFi，需带写操作请求头 |
| POST | `/api/wifi/connect` | `ssid`、`password` |
| POST | `/api/wifi/disconnect` | 断开 STA 连接并清除保存的 WiFi 凭据 |

`confirm=full_power` 是兼容早期客户端保留的固定字段值，实际仍按当前 `pulseMs` 与 30% 限幅执行，不会全功率冲激。

温度参数须满足 `10 <= low < target < high <= 55`，且目标温度与上下限之间至少留出 0.2 °C 间隔。`enabled` 支持 `true`、`false`、`on`、`off`、`1`、`0`，省略时按停用处理。

局域网请求示例：

```powershell
curl.exe http://192.168.1.1/api/status
curl.exe -X POST -H "X-PL530-Request: 1" -d "target=25&high=30&low=20&enabled=false" http://192.168.1.1/api/settings
curl.exe -X POST -H "X-PL530-Request: 1" http://192.168.1.1/api/control/stop
```
