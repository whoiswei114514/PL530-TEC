# 精密 PID 实验版

**这版代码目前只跑过热模型仿真和主机单元测试，还没上板实测，目标是把恒温稳态压到约 ±10 mK。原版 30 分钟烤机和单纵模表现对应的是根目录原版固件，不要直接套到新版上。**

这套工程独立放在 `firmware/precision_pid/` 下维护，不影响根目录原版 `src/`、`include/` 和构建配置。两版固件跑在完全相同的硬件上，按需要挑一个编译烧录就行。

## 控温算法与决策

- **双向 PID**：正输出加热、负输出制冷，具体对应哪个驱动通道仍由方向检测确定。
- **取消死区与起步下限**：去掉了原版 30–60 mK 死区和 10% 起步驱动。就算温升率已经趋近于零，只要还没回到目标温度就会持续积分纠偏。
- **测量微分与双滤波**：微分只作用于测温值本身，并配合独立的一阶滤波，避免改目标温度时微分项甩出尖峰。
- **真实采样间隔与双抗饱和**：积分按实际采样间隔累加，在占空比撞到输出限幅或变化率限幅时自动做条件抗积分饱和。
- **限幅标注与硬限保留**：正常 PID 输出受限幅和斜率约束，顶满限幅且仍有温差时状态会标成“输出限幅”，不会假装达标；一旦触及 10/55 °C 硬限，仍按原版逻辑全力往安全区拉回。
- **目标内稳定判据**：必须攒够约 120 秒的**未滤波原始样本**，且期间最大目标误差 ≤ 10 mK、峰峰值 ≤ 20 mK 才算达标。光看滤波曲线平或者瞬时误差小都不算。

测量微分、积分状态保持和抗饱和参考了 [Arduino PID_v1](https://github.com/br3ttb/Arduino-PID-Library) 与 [QuickPID](https://github.com/Dlloydev/QuickPID) 的写法，再按这套双向 TEC 和硬件保护需求改写。

## 采样、PWM 与参数隔离

TMP117 改为连续转换并开启 **8 次硬件平均**，单次转换约 124 ms，主循环每 200 ms 取一次新值。PID 内部全用双精度浮点算，遇到重复或逆序时间戳会直接跳过。传感器原始分辨率是 7.8125 mK；需要留意的是，控温稳得住和绝对温度准不准是两码事。

PWM 频率维持 1 kHz，分辨率从原版 10 位拉高到 ESP32-S3 支持的 **14 位**，状态接口上报量化后的实际占空比请求。原有的方向互锁、10–55 °C 硬限、采样超时关断和故障锁定全部保留。

参数存放在独立的 NVS 命名空间 `pl530_pid`，不会动原版 `pl530_tec` 的配置和方向记录。第一次从原版刷过来后，记得重新跑一遍方向检测。

## 编译与界面

在仓库根目录执行：

```powershell
pio run -d firmware/precision_pid -e precision_pid -j 1
pio run -d firmware/precision_pid -e precision_pid -t upload --upload-port COM10
```

把 `COM10` 换成实际串口，接线与进下载模式方法见 [编译与烧录](../../docs/编译与烧录.md)。

连上板子打开原来的网页地址，页面会展示四位小数温度、积分输出分量、原始温度峰峰值、最大目标误差和当前温控状态。停机状态下可以在“PID 整定”面板直接调参并保存。

## 默认整定与手调建议

| 参数 | 默认值 | 单位 |
|---|---|---|
| Kp | 20 | %/°C |
| Ki | 0.20 | %/(°C·s) |
| Kd | 40 | %·s/°C |
| 测量滤波时间常数 | 0.6 | s |
| 微分滤波时间常数 | 2.0 | s |
| 正常控制输出上限 | 30 | % |
| 输出变化率上限 | 15 | %/s |
| 积分幅度上限 | 30 | % |

默认参数只是个保守起点，上板后先用小功率观察热响应再手调：有持续静差通常要加大 `Ki`；来回振荡就减小 `Kp`/`Ki` 或加些微分阻尼；经常顶在“输出限幅”先查散热、热负载和电源带载，再决定要不要放开 30% 输出上限（硬温度保护不受正常上限约束，外部电源限流还是要配好）。

接口方面，`GET /api/pid` 返回整定参数、P/I/D 分量、限幅状态、控温决策与原始温度统计；`POST /api/pid` 仅在停机且无锁定故障时接受完整的八项参数，校验规则与原接口一致。

## 串口日志与稳态分析

每个有效采样周期会在串口吐出一行 CSV：

```text
PIDCSV,millis,rawC,filteredC,targetC,dutyPercent,pPercent,iPercent,dPercent,stateKey
```

上板测试时先等系统接近稳态，再连续录制至少 30 分钟（算上脚本默认跳过的前 10 分钟，完整日志至少要录 40 分钟），顺便也测测环境变化或热负载扰动。把完整串口日志存成文件后，在仓库根目录跑分析脚本：

```powershell
python firmware/precision_pid/tools/analyze_log.py test-results/pid-run.log --settle-seconds 600 --duration-seconds 1800
```

脚本直接用**未滤波原始温度**去卡 ±10 mK 目标误差、20 mK 峰峰值、采样连续性、目标一致性和控制状态，输出均值、标准差和通过与否。如果关心绝对温度准确度，另拿校准过的温度计对一下探头与被控点温差。

## 软件测试

根目录执行 `npm test` 会一并跑原版回归以及新版的控制器、传感器、PID 核心、NVS 存储和真实 `/api/pid` 接口处理测试；网页和日志工具测试单跑：

```powershell
node firmware/precision_pid/tests/web_ui_test.cjs
python firmware/precision_pid/tests/test_analyze_log.py
```

热模型测试覆盖了冷热负载、目标与负载阶跃、执行器延迟、采样抖动和 TMP117 量化，用来验证算法和抗饱和逻辑本身；最终样机能稳到什么程度，还是以上板录下来的原始温度日志为准。
