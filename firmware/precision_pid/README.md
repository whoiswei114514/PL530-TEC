# 精密 PID 实验版

**新版代码未经实机验证，恒温整定目标为约 10 mK。原版已完成 30 分钟烤机，维持单纵模不跳模、功率稳定；新版仍需上板整定与记录。**

本目录为独立 PlatformIO 工程，保留根目录的原版 `src/`、`include/` 和构建配置。两版使用相同硬件，按所选工程分别编译、烧录。

## 温控与决策

- 双向 PID：正输出加热，负输出制冷，实际通道由方向检测结果决定。
- 持续温差持续积分：没有 30–60 mK 的旧死区，也没有默认 10% 驱动。即使温升率接近零，只要偏离目标，仍继续修正。
- 微分作用于测量值并独立滤波，避免目标温度变化引起微分突跳。
- 积分按真实采样间隔累加，并对幅度、变化率饱和做条件抗积分饱和。
- 正常 PID 调节受输出限幅和变化率限制；达到限幅而仍有温差时显示“输出限幅”，不判定恒温达标。硬温度恢复保留原版全力纠正行为。
- “目标内稳定”需要约 120 秒未滤波样本，最大目标误差不超过 10 mK，峰峰值不超过 20 mK。零温升率、滤波曲线平直或瞬时误差小都不单独作为达标条件。
- 窗口依据连续采样时长判定，不要求固定 500 个样本；软件 I²C 读取会增加实际轮询间隔。达到 1 秒采样间隙、目标改变或样本失效时仍重新积累证据。

实现参考 [Arduino PID_v1](https://github.com/br3ttb/Arduino-PID-Library) 与 [QuickPID](https://github.com/Dlloydev/QuickPID) 的测量微分、积分状态和抗饱和思路，结合本项目的双向 TEC、采样抖动与输出保护实现。

## 采样与输出

TMP117 配置为连续转换、8 次硬件平均，转换周期约 124 ms，主程序每 200 ms 读取新转换。PID 内部使用双精度计算，重复或逆序时间戳不参与调节。传感器原始码分辨率为 7.8125 mK；稳定性与绝对温度准确度是不同指标。

PWM 保持 1 kHz，分辨率由原版 10 位提高至 ESP32-S3 支持的 14 位。状态接口报告量化后的实际请求占空比。原有方向互锁、10–55 °C 硬限制、采样超时关断与故障锁定保留。

新版使用独立 NVS 命名空间 `pl530_pid`，不修改原版 `pl530_tec` 的参数或方向记录。首次烧录新版后需重新检测 TEC 方向。

## 编译与使用

在仓库根目录执行：

```powershell
pio run -d firmware/precision_pid -e precision_pid -j 1
pio run -d firmware/precision_pid -e precision_pid -t upload --upload-port COM10
```

将 `COM10` 替换为实际串口。硬件接线与下载步骤见 [编译与烧录](../../docs/编译与烧录.md)。

连接设备后打开原有网页地址。网页显示四位小数温度、积分输出、原始温度峰峰值、最大目标误差和当前温控决策。停止温控后，可在“PID 整定”中调整并保存参数。

## 默认整定

| 参数 | 默认值 | 单位 |
|---|---|---|
| Kp | 20 | %/°C |
| Ki | 0.20 | %/(°C·s) |
| Kd | 40 | %·s/°C |
| 测量滤波时间常数 | 0.6 | s |
| 微分滤波时间常数 | 2.0 | s |
| 正常控制输出上限 | 30 | % |
| 输出变化率上限 | 15 | %/s |
| 积分幅度上限 | 30 | % |

默认值是整定起点。先检查小功率热响应，再根据样机调整：持续静差通常需要非零 Ki；振荡时减小 Kp/Ki 或增加微分阻尼；长期处于输出限幅时检查热负载、散热与供电，再决定是否提高输出上限。保持必要外部限流，硬温度保护不受正常 PID 上限限制。

`GET /api/pid` 返回整定参数、P/I/D 分量、输出限幅状态、决策和原始温度统计。`POST /api/pid` 仅在停机且无锁定故障时接受所有八项参数，使用与原接口相同的来源校验。

## 实测记录

每个有效采样输出一行串口记录：

```text
PIDCSV,millis,rawC,filteredC,targetC,dutyPercent,pPercent,iPercent,dPercent,stateKey
```

先等待进入稳态，再连续记录至少 30 分钟，并测试环境变化或热负载扰动。保存完整串口日志后，在仓库根目录执行：

```powershell
python firmware/precision_pid/tools/analyze_log.py test-results/pid-run.log --settle-seconds 600 --duration-seconds 1800
```

默认跳过前 10 分钟、检查随后 30 分钟，因此日志至少覆盖约 40 分钟。工具使用**未滤波温度**检查 ±10 mK 目标误差、20 mK 峰峰值、采样连续性、目标一致性和控制状态，输出均值、标准差及判定结果。另用校准温度仪器核对探头与被控对象的温度关系。

日志的全部温度与 P/I/D、输出数值必须有限，目标及实际输出必须在控制器范围内。异常控制数值不会因为原始温度恰好平稳而通过验收；统计仍只使用未滤波温度。

## 软件测试

在仓库根目录执行 `npm test`，同时运行原版回归和新版控制器、传感器、PID 核心、参数存储及真实 PID 接口处理函数测试。网页和日志工具测试执行：

```powershell
node firmware/precision_pid/tests/web_ui_test.cjs
python firmware/precision_pid/tests/test_analyze_log.py
```

模型测试包含冷热负载、目标变化、负载阶跃、执行器延迟、采样抖动及 TMP117 量化；它用于检查算法行为，样机性能以实测日志为准。
